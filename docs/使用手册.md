# 使用手册（本地访谈转录与会议纪要系统）

本工具在你的 Windows 电脑上完成全部工作：音频转码、语音识别、说话人分离、纪要生成。
录音不会上传到任何服务器，也不需要 OpenAI / 阿里云 / 讯飞等付费 API。

---

## 1. 第一次使用

### 1.1 安装

```powershell
cd C:\src\speech_conversion
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

安装脚本会：

1. 检查 CPU / 内存 / 磁盘 / Python；
2. 下载 FFmpeg 到 `tools\ffmpeg`（约 90MB，只需一次）；
3. 创建 `.venv` 虚拟环境并安装 PyTorch(CPU) + WhisperX + pyannote.audio（约 2–3GB）；
4. 检测 Ollama，可选用 winget 安装并拉取 `qwen3:8b`（约 5GB）；
5. 打印自检结果。

如果需要自己控制每一步，也可以手动执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
ollama pull qwen3:8b
```

### 1.2 配置 Hugging Face Token（说话人分离必需）

1. 注册 <https://huggingface.co> 并登录；
2. 打开 <https://huggingface.co/pyannote/speaker-diarization-community-1>，点击同意条款；
3. 打开 <https://huggingface.co/settings/tokens> 新建一个 **Read** 权限的 Token；
4. 启动应用 → 右上角 **设置** → 粘贴 Token → 保存。

> Token 只写入本机 `secrets\hf_token.txt`（已在 `.gitignore` 中排除），不会出现在日志、界面回显或导出文件中。

### 1.3 启动

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

浏览器会自动打开 <http://127.0.0.1:7860>。如果 Ollama 已安装但未运行，脚本会在后台启动 `ollama serve`。

## 2. 界面与操作流程

### 2.1 新建项目

左侧点 **＋ 新建访谈** → 拖入音频（M4A / MP3 / WAV / FLAC / MP4…）→ 可填项目名称 → **上传并创建**。

创建后会显示文件名、时长、大小与格式。项目保存在 `projects\<项目ID>\`。

### 2.2 音频转录

「音频转录」页设置：

| 设置 | 建议 |
| --- | --- |
| 识别语言 | 中文访谈选「中文（普通话）」，日语选「日语」；只有确实不确定时才用自动检测 |
| Whisper 模型 | 默认 `medium`；追求精度用 `large-v3`（内存占用约 2 倍、速度更慢） |
| 说话人数量 | 两人访谈建议「固定 2 人」，pyannote 会更稳定 |
| CPU 线程数 | 默认 = 逻辑核心数 − 4（本机 12 核 → 8） |
| 计算精度 | `int8`（CPU 最快） |
| 批量 / Beam | 默认 8 / 5，遇到内存不足就把批量降到 4 |
| 说话人分离 | 需要 HF Token；关闭则整段记为单一说话人 |
| 强制对齐 | 可选，用 wav2vec2 生成词级时间戳；约多花 0.2–0.5 倍录音时长，首次下载约 2.5 GB 模型 |

点 **开始转录**，可在「进度与日志」看到当前阶段、百分比与每一步日志。
中途点 **取消任务**：已完成的分段结果会保留，下次点开始会跳过这些分段。

> 已有初稿但结果异常（例如出现大量重复句子）时，可用 **重建逐字稿（清理异常段落）**：
> 它只用已缓存的识别结果重新合并，不会重新识别音频，并会自动过滤「提示词复读」与
> 重复循环段落。原始识别结果仍完整保存在 `asr/chunks/` 下。

> **切分点不准时用「词级对齐（改善切分点）」**：
> 说话人被切错（A 的前半句和 B 的后半句连在一行）通常是时间戳精度不够：
> 没有词级时间时，程序只能按字符比例把一整段文字切开。点这个按钮会复用已有的识别结果，
> 只追跑一遍声学对齐（不重新识别文字，耗时约 0.2–0.5 倍录音时长），然后按真实字边界重新切分。
> 它只刷新**机器初稿**，不会改动你的校对版（`edited.json`）。
> 注意：它修的是“切到哪里”，不能把分离判错的人纠正过来——那种情况请改归属或重跑分离。

> **整段被判错人时用「二次声纹校验（纠正归属）」**：
> pyannote 偶尔会把两个人对调几秒（典型现象：提问分给了受访人、回答分给了采访人）。
> 这个按钮会重新提取每个发言片段的声纹并全局聚类，只翻转“证据明确”的片段（约 1 分钟）。
> 原分离结果会自动备份到 `diarization/raw.before_refine.json`，可随时对照。

阶段耗时记录在项目的「阶段耗时」面板中，同时写入 `logs\timings.json`。

### 2.3 逐字稿编辑

- 顶部播放器：点任意时间戳可跳转播放并高亮对应段落；
- 顶部版本下拉：在「自动（优先校对版）/ 机器初稿 / 人工校对版」之间切换；
  对齐、重建、声纹校验**只改机器初稿**，如果已经保存过校对版，页面会显示
  「机器初稿已更新」横幅，点「查看新初稿」即可看到新结果；
- 说话人下拉框：修正单段归属；
- 文本框：直接修改文字（自动保存，1.5 秒防抖）；
- 顶部「说话人」区域：改成「访谈者」「受访者」等真实角色名称，保存后同步到导出与纪要；
- 「保存」按钮可手动触发；「放弃校对版」会删除人工校对文件并回到机器初稿。

校对版单独保存在 `transcript\edited.json`，机器初稿 `transcript\draft.json` 不会被覆盖。
如果重新转录导致初稿变化，界面会提示「初稿已更新，校对版基于旧初稿」。

### 2.4 AI 纪要

「AI 纪要」页：

1. 选择模板（普通会议纪要 / 定性研究访谈纪要）；
2. 选择本地 Ollama 模型（默认 `qwen3:8b`）；
3. 可选「生成后对照逐字稿检查依据」；
4. 点 **生成纪要**。

生成过程是 map → reduce → compose → verify：

1. 逐字稿按时间戳与发言边界切成约 4500 字的段；
2. 每段抽取「事实 + 时间戳 + 原文引用」，结果写入 `summary\chunks\NNN.json`；
3. 合并去重（事实过多时分层合并）；
4. 按模板生成中文纪要；
5. 用模型复核结论是否在证据中有依据，结果展示为「依据核查」。

每段结果都会落盘，失败后重新点生成会复用已完成的段；勾选「忽略缓存」可强制重跑。

「编辑纪要」可以对 Markdown 做人工修订，「保存修改」只影响纪要文件，不会动逐字稿。

### 2.5 导出

| 格式 | 内容 |
| --- | --- |
| TXT | 带时间戳与说话人的逐字稿 |
| Markdown | 逐字稿 + 已生成的纪要 |
| SRT | 可导入剪映 / Premiere / YouTube |
| DOCX | 排版好的逐字稿与纪要 |
| JSON | 完整结构化数据（含分段、说话人、词级时间戳） |

可选择导出「机器初稿 / 人工校对版 / 自动」。文件同时副本保存在 `projects\<ID>\exports\`。

## 3. 数据位置

```
projects/<20261103-113705-a1b2c3>/
  project.json           项目元数据、设置、阶段状态
  audio/source.m4a       原始录音（不修改）
  audio/normalized_16k.wav  转码缓存（删掉会自动重建）
  asr/manifest.json      切分计划与识别参数
  asr/chunks/000.json    每个分段识别结果（断点续跑）
  diarization/raw.json   说话人分离原始输出
  transcript/draft.json  机器初稿
  transcript/edited.json 人工校对版（存在则导出/纪要优先使用）
  summary/chunks/*.json  分段抽取结果
  summary/final.json     最终纪要（含证据、核查结果）
  summary/final.md
  logs/job.log           处理日志
  logs/timings.json      各阶段耗时
```

删除项目会删除整个目录（界面上的「删除项目」按钮有二次确认）。

## 4. 常见错误与处理

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 页面提示「未找到 FFmpeg」 | 未安装或路径被移动 | 重新运行 `install.ps1`，或把 `ffmpeg.exe` 放到 `tools\ffmpeg\bin\`，或设置 `INTERVIEWAI_FFMPEG` |
| 说话人分离失败：缺少 Hugging Face Token | 未配置 Token | 设置页填入 Token |
| 说话人分离失败：403 / gated repo | 未在模型页同意条款 | 打开模型页面点 Agree，再重试 |
| 所有段落都是「说话人 A」 | 关闭了分离，或分离失败 | 打开「说话人分离」或查看日志中的失败原因；可用「仅重跑说话人分离」 |
| 「无法连接本地 Ollama」 | Ollama 未运行 | 运行 `ollama serve`，或用 `start.ps1` 启动；设置页确认地址为 `http://127.0.0.1:11434` |
| Ollama 返回 404 / model not found | 模型未拉取 | `ollama pull qwen3:8b`，或改选已安装的模型 |
| 转录进度长时间不动 | CPU 推理较慢（约实时 1–3 倍） | 正常现象；可降低模型、减少 beam、关闭对齐 |
| 内存不足 / 崩溃 | `large-v3` + 大 batch | 换 `medium`、batch 降到 4、关闭对齐；分离与识别本来就是串行执行 |
| 界面提示「已有任务正在运行」 | 同一时间只允许一个重任务 | 等当前任务完成或取消 |
| 转录结果出现重复句子 | 长静音造成的 Whisper 幻觉 | 已默认关闭 `condition_on_previous_text`；仍出现时可在逐字稿中删除 || 逐字稿里反复出现「请用简体中文并加上标点符号」等句子 | Whisper 把 `initial_prompt` 当音频复读 | 新版本已不再发送提示词；旧稿件到「音频转录」页点 **重建逐字稿（清理异常段落）** |

## 5. 隐私说明

- 服务只监听 `127.0.0.1`，不接受外部网络访问；
- 不包含任何遥测、崩溃上报、云 API 调用；
- 首次运行会联网下载模型权重（Hugging Face / Ollama），之后可完全离线；
- Token 不写日志、不回显；
- 录音、逐字稿、纪要全部保存在本机项目目录，由你自行备份或删除。
