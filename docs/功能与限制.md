## 二、已知限制（请务必阅读）

1. **说话人分离已验证可以跑通，但准确率需你判断。**
   40 秒合成片段：2 位说话人、0.34× 实时；真实 38:15 双人访谈：2 位说话人、
   2115.8 s（0.92× 实时），187 段中 95/92 段分布。短插话、重叠语音、
   音色相近的说话人仍会错，且短句容易被打上「说话人不确定」。

2. **识别准确率数据来自 TTS 合成语音**（字符相似度 0.893）。
   合成语音清晰无噪声，真实访谈（口音、噪声、远场）会明显更差，请勿据此判断可用性。

3. **没有词级时间戳。** WhisperX 3.8.6 的批处理路径只返回句子级时间戳。
   当一句话中间发生说话人切换时，应用按字符比例切分（不是按词）。
   勾选「严格对齐」会额外下载 wav2vec2 对齐模型（约 1.2GB），速度更慢。

4. **句内语言自动切换不可靠。**
   自动检测按音频块进行，中英/中日混说建议指定主语言；同一句话内切换语言会被
   识别为单一语言或被截断。需求中「无法可靠自动识别句内语言切换需说明限制」——
   这就是明确限制，建议人工分段后分别导入或在逐字稿中修正。

5. **模型能力限制会导致错误。** 合成测试中「掉毛」被识别为「吊毛」，数字被写成阿拉伯数字。
   应用不会自动改写模型输出，只在低置信度处打标。

6. **8B 模型在本机很慢。** 实测 3.4–3.8 token/s（6 线程）。
   一次分段抽取约 2 分钟，90 分钟访谈（约 15–20 段）预计 40–70 分钟。
   想更快可改用 `qwen3:4b` / `qwen3:1.7b`，或换更强的 CPU / 独立显卡。

7. **torchcodec 在 Windows 上不可用。** torchcodec 0.7 仅支持 FFmpeg ≤ 7，
   而 Windows 上只有 FFmpeg 8/9 的 shared 构建。本应用因此不使用 torchcodec：
   FFmpeg CLI 负责解码，pyannote 接收内存波形。导入时会出现一条无害警告。

8. **长录音的内存占用。** 分离阶段会把整段 16k  waveform 读入内存（90 分钟约 345MB），
   加上模型约 1.5–2GB；本机 32GB 足够，8GB 机器可能紧张。

9. **只支持 Windows**（脚本为 PowerShell / 批处理），Web UI 只监听本机回环地址。

10. **纪要仍需人工复核。** 「依据核查」只是模型自检，可能漏判；关键数字、决策、
    行动事项必须对照时间戳逐条确认。

11. **未做多用户/权限体系。** 这是单人本地工具，无登录、无并发写入保护
    （同一时间只允许一个重任务）。
